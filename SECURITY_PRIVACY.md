# Security and Privacy

No secrets, external credentials, or server-side personal data are required. Browser persistence is local to the prototype and is not a secure multi-user datastore.

All form inputs are schema-validated. HTML is rendered as text, not arbitrary markup. Release gates require rights, consent, provenance, safety, rating, accessibility, and approval metadata. Future production work must add authentication, server authorization, encrypted storage, audit logging, rate limiting, CSP, and deletion/export workflows.
